## Overview

The project implements **two approaches** to predicting the **VAD** emotional dimensions of Italian sentences:

| Approach | Description | Output |
|-----------|-------------|--------|
| **Task A** | Three separate BERT models, one per dimension (Valence, Arousal, Dominance). Single-target regression. | 3 checkpoints, per-dimension metrics |
| **Task B** | One BERT model predicting **V, A and D** jointly. Multi-target regression. | 1 checkpoint, joint metrics |

- **Valence (V)**: pleasantness (1 = very negative, 5 = very positive)
- **Arousal (A)**: activation intensity (1 = calm, 5 = excited)
- **Dominance (D)**: control (1 = dominated, 5 = dominant)

Both tasks fine-tune a pretrained Italian BERT (`dbmdz/bert-base-italian-cased`), freezing the bottom transformer layers and training only the top layers plus a linear regression head, with early stopping on validation loss. The reported metrics are **MAE** (Mean Absolute Error) and **Pearson r** for each dimension.

## EmoITA dataset

EmoITA provides Italian sentences annotated with **V, A, D** on a 1-5 scale.

- **Development set**: used for **train** and **validation** (80/20 split).
- **Test set**: unlabeled, used only in Task B.
- **Test set (gold labels)**: used **only** for final evaluation, never for training.

Expected CSV format: a `text` column, plus `V`, `A`, `D` for annotated data. An optional `id` column can be used to align predictions with gold labels (Task B).

## Task A: single-target regression (V, A, D separately)

One dedicated BERT model per dimension.

### 1. Prepare the data

```bash
python taskA/code/prepare_taskA_datasets.py
```

Reads `taskA/data/Development set.csv` and `Test set - Gold labels.csv`, and creates train/val/test splits for **V**, **A** and **D** in `taskA/data/`.

### 2. (Optional) Inspect the data

```bash
python taskA/code/check_datasets.py
```

Prints columns, row counts and a preview of every CSV in `taskA/data/`.

### 3. Train

One config per dimension. Validation uses `val_*`; the official test uses the `*_test.yaml` configs.

```bash
cd taskA/code
python train.py --config ../config_valence.yaml
python train.py --config ../config_arousal.yaml
python train.py --config ../config_dominance.yaml
```

Checkpoints are saved to `taskA/risultati/` (e.g. `model_valence.pth`).

### 4. Predict

On the validation set (consistent with training):

```bash
python predict.py --config ../config_valence.yaml
```

On the official test set (gold labels):

```bash
python predict.py --config ../config_valence_test.yaml
```

Predictions are written to `taskA/risultati/model_*_pred.csv`.

### 5. Evaluate

```bash
python evaluation.py --config ../config_valence_test.yaml
```

Writes `model_*_results.txt` with MAE and Pearson r. Repeat for arousal and dominance.

### 6. Compare the three dimensions

```bash
python comparativa_taskA.py
```

Prints a table and saves `taskA/risultati/comparativa_taskA.png`.

### Implementation notes

For Task A, predictions are evaluated directly against the gold-labeled test set rather than against an unlabeled test set requiring a separate submission/merge step, which is a simplification relative to the official challenge protocol (where predictions would be produced on an unlabeled test set and merged with gold labels afterward). Gold labels are used **exclusively** for the final evaluation, after training is complete — they never enter the training or model-selection loop, so there is no leakage.

## Task B: multi-target regression (joint VAD)

One BERT model predicting V, A and D together.

### 1. Prepare the data

```bash
python taskB/code/prepare_dataset.py
```

Reads `taskB/data/Development set.csv` and creates `taskB/data/train.csv` and `val.csv` (80/20).

### 2. Train

```bash
python taskB/code/train.py
```

Checkpoint saved to `taskB/risultati/model.pth`; per-epoch train/val loss saved to `train_losses.txt` / `val_losses.txt`.

### 3. Predict

```bash
python taskB/code/predict.py
```

Reads `taskB/data/Test set.csv`, writes predictions to `taskB/risultati/my_predictions.csv` (columns `V_pred`, `A_pred`, `D_pred`).

### 4. Evaluate

```bash
python taskB/code/evaluation.py
```

Merges `my_predictions.csv` with `Test set - Gold labels.csv` (on `id` if present, otherwise `text`) and writes MAE/Pearson r for V, A, D to `taskB/risultati/risultati.txt`.

### 5. Visualize

```bash
python taskB/code/plot_loss.py       # saves risultati/loss_curve.png
python taskB/code/tabella_taskB.py   # prints the results table
```

### 6. Compare Task A vs Task B

```bash
python taskB/code/comparativa_AB.py
```

Reads Task A results (`taskA/risultati/model_*_results.txt`) and Task B results (`taskB/risultati/risultati.txt`), prints a table and saves `taskB/risultati/comparativa_AB.png`.

All Task B scripts resolve paths relative to the repository root, so they can be run from any working directory.

## Full pipeline

```bash
# 1. Environment
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# 2. Data
python taskA/code/prepare_taskA_datasets.py
python taskB/code/prepare_dataset.py

# 3. Task A: train -> predict -> evaluate, for each dimension
cd taskA/code
for dim in valence arousal dominance; do
  python train.py --config ../config_${dim}.yaml
  python predict.py --config ../config_${dim}_test.yaml
  python evaluation.py --config ../config_${dim}_test.yaml
done
python comparativa_taskA.py
cd ../..

# 4. Task B: train -> predict -> evaluate
python taskB/code/train.py
python taskB/code/predict.py
python taskB/code/evaluation.py
python taskB/code/plot_loss.py
python taskB/code/comparativa_AB.py
```

## Design notes

Task A and Task B originally duplicated the dataset class, the model class and the training loop almost verbatim, differing only in single- vs multi-target output. That logic now lives once in `common/`:

- **`common/dataset.py`** — `EmoITADataset` handles both cases: pass a single target column for Task A, three for Task B, or none for inference-only datasets.
- **`common/model.py`** — `BertVADRegressor` takes `output_dim` (1 or 3) and freezes the bottom transformer layers; layer-name parsing is robust to both `encoder.layer.N` and `layer.N` naming across `transformers` versions.
- **`common/engine.py`** — the train/eval loop, early stopping and checkpoint saving are shared; `set_seed()` seeds `torch`/`numpy`/`random` from the config's `seed` field (previously declared in the configs but never actually applied).
- **`common/metrics.py`** — MAE and a NaN-safe Pearson r (returns 0.0 for constant vectors instead of raising) shared by both evaluation scripts.

Task A and Task B keep their own YAML schema and CLI, since the two tasks are conceptually different (single- vs multi-target) — only the underlying implementation is unified. Both entry points now use `argparse` instead of manual `sys.argv` parsing, and all scripts resolve file paths relative to the repository root rather than the current working directory, so they behave the same regardless of where they're invoked from.

## Configuration

### Task A — example `config_valence.yaml`

```yaml
dataset: taskA/data/train_valence.csv
testset: taskA/data/val_valence.csv      # or test_valence.csv for the official test
target_col: V                            # V, A or D
model_save_path: taskA/risultati/model_valence.pth

tokenizer:
  name: dbmdz/bert-base-italian-cased

training:
  epochs: 8
  batch_size: 16
  learning_rate: 0.00002
  seed: 42
  patience: 3
```

### Task B — `config.yaml`

```yaml
dataset:
  train: "data/train.csv"
  val: "data/val.csv"
  test: "data/Test set.csv"
  gold: "data/Test set - Gold labels.csv"

predictions_path: "risultati/my_predictions.csv"
results_path: "risultati/risultati.txt"

tokenizer:
  name: "dbmdz/bert-base-italian-cased"
  max_len: 64

params:
  batch_size: 16
  lr: 0.00003
  num_epochs: 8
  seed: 42
  patience: 3
```

## Results

Results on the evaluation/test sets after training and evaluation (reproducible via the [full pipeline](#full-pipeline)).

### Task A — three models (single-target)

| Dimension | MAE | Pearson r |
|------------|-----|-----------|
| Valence (V) | 0.364 | 0.632 |
| Arousal (A) | 0.310 | 0.557 |
| Dominance (D) | 0.287 | 0.541 |

### Task B — one model (multi-target)

| Dimension | MAE | Pearson r |
|------------|-----|-----------|
| Valence (V) | 0.323 | 0.711 |
| Arousal (A) | 0.301 | 0.589 |
| Dominance (D) | 0.281 | 0.598 |

### Discussion

Pearson r falls in the **0.54-0.71** range and MAE between **0.28 and 0.36** (on a 1-5 scale). Both approaches reach moderate-to-good correlation with gold labels and contained absolute error. Valence has a slightly higher MAE under Task A; Task B shows a higher Valence correlation. Dominance has the lowest MAE in both setups. Task A trains three specialized models (three training runs, per-dimension outputs); Task B trains a single multi-output model (one run, one results file). Results depend on dataset, hyperparameters and split — neither approach is declared "better"; both are valid and reproducible.

Comparison charts (`comparativa_taskA.png`, `comparativa_AB.png`) visualize these results; numeric values are in `taskA/risultati/model_*_results.txt` and `taskB/risultati/risultati.txt`.
